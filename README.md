# VOXEL LEGEND

Windows 桌面程序。渲染使用 OpenGL 3.3 core，语言为 C++20，工具链为 MinGW-w64 g++。运行形态有两种：自由探索（本地存档），以及房间对局（大厅组队后切换到专用服务器）。

对局在一张由种子决定的场地上进行，六座圆坛全部生成。四支作战队伍各被分配一场互不相同的仪式；玩家沿建筑线索找到 Boss，取得服务器权威掉落的圣物，再将对应三件圣物放置到该仪式圆坛的三角区域。

## 1. 构建与运行

```powershell
.\build.ps1
```

| 产物                            | 用途                                             |
| ------------------------------- | ------------------------------------------------ |
| `voxel-legend.exe`            | 游戏客户端；`--room-server` 时为无头对局服务器 |
| `editor.exe`                  | 材质、模型、动画、数据包与结构编辑               |
| `tools/tree_lab/tree_lab.exe` | 树木生长步进沙盒                                 |

常用参数：

| 参数                                      | 作用                             |
| ----------------------------------------- | -------------------------------- |
| `--seed N`                              | 新建世界使用的种子               |
| `--no-save`                             | 关闭存档读写                     |
| `--frames N`                            | 运行 N 帧后退出                  |
| `--selftest N`                          | 无窗口压力测试，N 次迭代         |
| `--withertest` / `--watertest`        | 草皮枯萎、水流的无窗口测试       |
| `--seed-data`                           | 补齐缺失的`assets/data` 后退出 |
| `--room-server --port N --handoff PATH` | 无头对局服务器。默认端口 35535   |
| `--edit-structure [file]`               | 进入结构飞行建造                 |
| `--help`                                | 打印参数                         |

## 2. 对局规则

### 2.1 术语

| 术语     | 定义                                                   |
| -------- | ------------------------------------------------------ |
| 区块     | 32×16×32（x, y, z）体素                              |
| 区块列   | 同一 (x, z) 上叠放的 8 个区块，覆盖世界高度 128        |
| 可玩区   | 2048×2048 个区块列，列坐标 x、z 均为`[-1024, 1023]` |
| 边界环   | 可玩区外侧一圈区块列，列坐标扩到`[-1025, 1024]`      |
| 作战队伍 | 编号 1–4。每队一场仪式、一个角部署区                  |
| 观战队伍 | 编号 0。不部署，飞行且穿模                             |
| 圣物     | 十五种仪式物品，只能由服务器确认的 Boss 战利品产生      |
| 圆坛     | 六座仪式场地之一，与一场仪式绑定                       |

格边长为 0.5 个世界单位（`BLOCK_SCALE`）。

### 2.2 仪式分配

`ritual::roll(seed)` 将 6 场仪式洗牌，前 4 场按顺序分给队伍 1–4。其余 2 场本局无队伍认领，圆坛仍生成。

完成判定只检查本队配方，且只检查本队圆坛。结果写在客户端（笔记状态），不向全场广播胜负。

| 仪式     | 圣物                         |
| -------- | ---------------------------- |
| 元素之源 | 元素核心、原始之火、静滞之水 |
| 世界树   | 元素核心、生命嫩枝、根须织毯 |
| 世界主神 | 裁决天平、黄金冠冕、审判之书 |
| 溯时之蛇 | 裁决天平、鳞片沙漏、循环刻印 |
| 旧神残魂 | 深渊棱镜、上古图腾、残响符石 |
| 外神     | 深渊棱镜、旧神骸骨、无目雕像 |

配方之间允许共用圣物种类。每个 Boss 线索节点绑定一种圣物，权威完成接口保证该节点只掉落一次；具体节点与圣物的全局分配由后续建筑/Boss 编排负责。

### 2.3 房间

主菜单提供创建房间、加入房间、自由探索。

1. 主机进程在 TCP 端口上开启大厅，默认 `35535`。已有客人连接后端口不可改。
2. 大厅固定包含观战队。主机可再添加作战队，上限 4。玩家选择队伍。
3. 主机开始对局后，本机启动 `voxel-legend.exe --room-server`。名单经 `GameSaves/room_handoff.bin` 交给该进程。
4. 客人断开大厅，改为连接专用服务器。主机游戏进程同样作为该服务器的客户端。
5. 服务器以随机种子生成世界，不写存档。大厅在对局开始后关闭。

### 2.4 部署

作战队员进入对局后先进入部署界面。观战队员跳过此步骤。

| 项           | 值                                                                                 |
| ------------ | ---------------------------------------------------------------------------------- |
| 部署区       | 可玩区四角各一块。队伍`i`（0–3）的 x 侧由 `i & 1` 决定，z 侧由 `i & 2` 决定 |
| 区域尺寸     | 4×4 个区块列，即 128×128 格                                                      |
| 地图         | 默认黑色，2 像素白边。已加载的区块列按地表方块着色                                 |
| 选点         | 左键放置本队颜色的标记并重置倒计时；右键取消                                       |
| 可见性       | 同队标记互相可见                                                                   |
| 首次倒计时   | 10 秒。由服务器持有                                                                |
| 死亡后再部署 | 20 秒                                                                              |
| 落地后标记   | 由叉变为点，约 1.6 秒后消失                                                        |

倒计时结束时，服务器将玩家位置设到所选格的地表。在开场文本结束之前，客户端隐藏角色模型。

死亡后体征重置，再次进入部署界面，不重复开场文本。

### 2.5 开场文本

仅第一次部署、且本队有已分配仪式时播放。

1. 画面为全黑。鼠标可用，视角不锁定。
2. 句子淡入（约 0.4 秒）。淡入完成后，单击或按下任意键开始淡出。按键连发不计为新的一次输入。
3. 淡出结束后显示下一句。
4. 最后一句淡出后，隐藏解除，模型出现在已设定的落点，恢复移动与视角。

文本按仪式分写，只显示本队那场。旧神残魂为断续短句，外神夹杂音节。对局进行中不在屏幕顶端重复目标。`E` 打开背包后，左上角「笔记」可查看仪式名、原文，以及每件圣物的状态：尚未找到、已携带、已放上祭坛。

### 2.6 完成条件

圣物默认不可放置。仅当目标格同时满足以下条件时，右键可以放下手持圣物：

- 圣物属于本队配方所在圆坛
- 水平位置落在该圆坛的三角区域内
- 高度为坛面上一格
- 该格为空气或液体，且不与玩家碰撞体重叠

三件配方圣物同时存在于该三角区域的放置层时，本机 `ritualDone` 置位，笔记显示「仪式已完成」。挖掉已放置的圣物会使其回到掉落物；完成标记在置位后保持。

### 2.7 场地与边界

边界环内的地形按普通规则生成，含树木。环外不生成地形。结构只盖在可玩列上。旧版圣物平台暂保留为空地标，不再直接放置圣物。

浅灰雾颜色为 RGB `(0.78, 0.79, 0.80)`。

| 位置           | 雾                                                                                 |
| -------------- | ---------------------------------------------------------------------------------- |
| 可玩区内部     | 边界雾为 0。距离雾仍使用天空雾色与`FOG_DENSITY`                                  |
| 边界环内侧起   | `t = 0` 在环的内侧面，`t = 1` 在外侧面。可见度 `visualFog = min(t / 0.5, 1)` |
| `t ≥ 0.5`   | 完全不透明，直至外侧面                                                             |
| 从可玩区向外看 | 按片元世界坐标计算，不要求玩家站在环内                                             |

玩家位置被夹在边界环外侧面内侧（保留半宽）。雾浓度同时驱动心肺与吸气流失：`vitalRate = 0.012 * exp(3.4 * visualFog)`，单位为每秒，半深后饱和。

### 2.8 场地物体

位置在可玩区内用拒绝采样选取：距可玩区边缘至少 8 个区块列，任意两点的水平距离至少 96 格。当前仍保留 21 个兼容点（15 座空的旧版圣物平台 + 6 座圆坛）。

| 物体     | 几何                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------- |
| 旧版平台 | 以采样点为中心的 5×5 木板，高度为该点地表；平台上方 4 格清空，但不再生成圣物                        |
| 圆坛     | 半径 10 格（`dx² + dz² ≤ 100`）。`d² ≥ 64` 为圆石，内侧为石头。坛面上方 4 格清空               |
| 三角区域 | 坛面上的砖块区域。顶点相对坛心的格偏移为`(0,-6)`、`(5,3)`、`(-5,3)`，包含边界。整块三角落在石面内 |

圆坛高度取坛心的生成地表高度，与盖章时使用的高度一致。

### 2.9 生存与自由探索

非特权模式下持续结算体征。头、上胸、腰腹核心任一归零则死亡。另有饥饿、口渴、心肺、吸气，以及头、胸、核心、双手、双足的耐力。坠落、奔跑、游泳、挖掘产生消耗。

采集规则（掉落、硬度、耐久、工具标签）来自数据包。背包为左手 3 格、右手 3 格、主背包 27 格，另有上衣、短裤、鞋。数字键 1–3 选左手，4–6 选右手。

自由探索不启用第 2 节的分配、部署、边界雾与仪式完成。世界可创建、读取、存档与备份。特权模式可飞行。调试叠加与湿度视图在自由探索中可用，在房间对局中关闭。

正式房间已启用服务器权威 PvP 基础。镐子对玩家命中部位造成 14% 伤害，斧子造成 10%；同队和自身不受伤害。客户端只发攻击意图，服务器在前摇结束时根据背包、手部状态、冷却、距离、朝向、遮挡和部位命中盒决定结果。镐斧仍保留采集功能。

### 2.10 新手指南与建筑线索

每名正式阵营玩家进入专用服务器时固定获得一本不可消耗的 `Guide Book / 新手指南`。选中后右键打开 8 页静态 UI，内容覆盖移动、背包、左右手、阵营、圣物与祭坛、仪式、奥术、武器及键位。观战者不发放；指南不是随机建筑战利品。

`Clue / 建筑线索` 同样是真实、不可消耗的 Item，但坐标不写入 `ItemSlot`。建筑模块在专用服务器调用 `building_loot::Spawner::spawnClueAt(position, director, link)`，将掉落物网络 ID 绑定到阵营、阶段、目标建筑坐标、目标类型和可选奖励。普通 `spawnItemAt` 与随机表会拒绝未绑定线索，避免产生无法解释坐标的坏道具。

线索按阵营共享并严格顺序推进：错误阵营、跨阶段、重复领取都会被拒绝；一名队员拾取后，在线队友获得一份线索物品，并通过 `PlayDelta` 收到相同目标。目标可为线索建筑、奥术藏匿点或 Boss 巢穴；奥术节点可同时放置奖励和下一枚线索。Boss 节点未由服务器确认完成前不能推进；权威遭遇逻辑调用 `clue::Director::completeBoss` 后，才会在绑定地点附近一次性生成指定圣物。当前主线已有无 AI 的试炼守护者及房间同步；线索接口不会自行创建 Boss 或 Boss AI。

## 3. 奥术系统

正式房间现有 Fireball（火球术）、Freeze（冰封术）和 Heal（治疗术）三种奥术。它们都是可堆叠 8 个、成功使用时消耗 1 个的普通 Item；选中后按右键只发送一次施法意图。专用服务器校验背包、手部、冷却和当前动作，并权威决定投射物、目标、命中、伤害、状态和治疗。客户端不声明这些结果。

火球碰到世界或敌方玩家时爆炸：半径 3.0 world units，中心对每个现有 vitals 部位造成 12% 伤害，线性衰减到边缘 4.8%。存活目标获得 4 秒 Burning，每秒对每个部位造成 3% 伤害；同一施法者再次命中只刷新时间，不叠层。冷却 3 秒，同队和自身不受伤害。TTL 到期的火球直接删除。飞行体、拖尾、爆裂和燃烧粒子由所有客户端按同一服务器状态绘制，不含音效。

冰封术创建速度更快的蓝白单体投射物。命中敌方玩家时对每个 vitals 部位造成 8% 伤害，并施加 5 秒 Frozen；期间服务器禁止移动、跳跃和冲刺，但仍允许转动视角。重复冰封只刷新同一个状态的持续时间，冷却 10 秒。命中世界只产生冰晶爆裂，不产生范围伤害。

治疗术由服务器沿准星在 8 world units 内选择无遮挡、受伤且存活的同阵营玩家；没有合适队友时回退到施法者自己。成功后所有现有 vitals 部位分别增加最大值的 25%，不超过上限，也不能复活；目标满血时不会消耗物品或进入冷却。冷却 12 秒。服务器同步短暂的绿色/金色治疗脉冲和身体粒子。

三种卷轴都不会随机散落在地图或放入出生背包。建筑模块完成后，可将 `ITEM_ARCANE_FIREBALL`、`ITEM_ARCANE_FREEZE`、`ITEM_ARCANE_HEAL` 放入 `building_loot::Spawner` 的定点或权重表。自由探索模式暂不接入战斗奥术。

## 4. 工程结构

```
voxel-legend/
  build.ps1
  voxel-legend.exe
  editor.exe
  src/
    main.cpp          入口、菜单、大厅、对局主循环
    core/             配置、数学、噪声、OpenGL 加载
    world/            世界、玩家、体征、仪式、场地、结构、存档、数据包
    net/              房间协议、大厅、对局客户端、专用服务器

```

## 5. 运行时

主循环位于 `src/main.cpp`。界面状态包括开始菜单、世界列表、房间大厅、加入房间、加载、游戏中。

| 时钟           | 值                                            |
| -------------- | --------------------------------------------- |
| 物理步长       | 120 Hz（`FIXED_DT = 1/120`），每帧最多 8 步 |
| 方块更新       | 20 tick/秒（草皮枯萎、水流）                  |
| 昼夜           | 24000 tick / 日，实时约 1200 秒               |
| 客户端输入上报 | 约 20 Hz                                      |

世界按区块流式加载。水平加载半径 3 个区块，卸载半径为加载半径加 2。区块存储方块、水位、标记、树木 id、草皮贴面。网格在区块变脏后重建。

自由探索时，树木倒下、草皮与水流在客户端模拟，改动的列写入 `GameSaves/<世界名>/default/`，并保留按时间戳的备份。房间对局中，这些模拟在专用服务器上运行；客户端关闭本地树木物理，只应用服务器增量。

`src/plugin` 将行为与外观分开。`BlockStrategy` 负责放置、破坏、随机刻、邻居变化、交互与额外掉落。`EntityStrategy` 负责生成、刻、AI、受伤与交互。内置内容由 `BasicConstruction` 注册，数值 id 与 `enum Block` 的顺序一致，存档与世界生成依赖该顺序。外观文件不注册新方块或新实体。新行为在 `src/plugin/modules/` 中实现并注册；数值放在数据包中。

## 6. 网络

字节序为小端。套接字层加长度前缀。协议版本为 `kRoomProto`（`2609290105`）。版本不一致则拒绝握手。

### 6.1 大厅

类型：`LobbyHost` / `LobbyGuest`。

| 消息            | 方向         | 内容                         |
| --------------- | ------------ | ---------------------------- |
| Hello / Welcome | 连接         | 协议版本与欢迎               |
| Lobby           | 主机 → 客人 | 队伍与玩家名单               |
| JoinTeam        | 客人 → 主机 | 选队                         |
| MatchStart      | 主机 → 客人 | 开始对局，客人改连专用服务器 |

### 6.2 对局

类型：`GameClient` 对 `runRoomServer`。

| 消息                    | 方向             | 内容                                                             |
| ----------------------- | ---------------- | ---------------------------------------------------------------- |
| PlayHello / PlayWelcome | 握手             | 客户端 id、种子、出生点、队伍                                    |
| PlayInput               | 客户端 → 服务器 | 移动/攻击/施法/拾取意图、背包重排、方块编辑、挖掘、区块重同步请求 |
| PlayDelta               | 服务器 → 客户端 | 权威身体/背包/掉落/战斗事件、投射物/奥术事件/状态、玩家姿态、区块、树木、挖掘进度 |
| Deploy                  | 客户端 → 服务器 | `action`：0 取消，1 放置标记，2 死亡后重新打开部署。附带格坐标 |
| DeploySync              | 服务器 → 同队   | 当前标记（瞄准叉或淡出点）                                       |

移动由服务器按客户端意图固定步进，不采用客户端坐标、速度、落地/飞行声明或时钟。部署、摔落伤害、手足失能、背包物品总量、掉落拾取、PvP 伤害、火球碰撞与 Burning 均由服务器结算。方块改动、树皮、挖掘、倒下的树、区块版本与哈希由服务器下发。客户端用区块哈希发现偏差后请求整块重同步。

## 7. 资源

根目录为 `assets/`（`pack::root()`）。

### 7.1 数据包

路径：`assets/data/<包名>/`。内置包为 `vanilla`，描述文件为 `pack.def`（名字、标题、优先级）。

| 路径                                  | 内容                                                                 |
| ------------------------------------- | -------------------------------------------------------------------- |
| `block/<id>.def`、`item/<id>.def` | 显示名、种类、堆叠、硬度、耐久、效率、重量、工具标签、采集需求与掉落 |
| `entity/<id>.def`                   | 显示名与体征消耗速率                                                 |

后加载的包按字符串 id 覆盖，优先级高者生效。`_hand`、`_sod` 为特殊条目。Data Pack Editor 读写这些文件。启动时 `data::apply()` 写入运行时表。

### 7.2 外观

外观文件不参与注册。未知字段在 `.model` 与 `.rand` 中保留并原样写回。

| 路径                                                    | 内容                               |
| ------------------------------------------------------- | ---------------------------------- |
| `materials/tiles/`、`materials/extras/`             | 贴图 PNG，合成方块图集             |
| `materials/blocks/<id>.model`                         | 方块空间四边形：顶点、UV、贴图茎名 |
| `materials/blocks/<id>.rand`                          | 材质浮点参数                       |
| `entities/player.model`、`entities/clothes/*.model` | 实体体素部件与皮肤                 |
| `entities/anims/*.animation`                          | 骨骼动画                           |
| `entities/*.hold`                                     | 物品相对骨骼的握持                 |

### 7.3 结构蓝图

路径：`assets/structures/*.vlstruct`。

文件布局：8 字节魔数 `VLSTRUCT`，`uint16` 版本（当前为 1），三个 `int32` 尺寸 `sx, sy, sz`，随后为 `sx*sy*sz` 字节的方块 id。单轴尺寸限制为 1–64。超出当前方块数量的 id 读入时改为空气。

对局中的圣物平台与圆坛由 `structure::stampColumn` 按种子直接写入地表，不读取 `.vlstruct`。该目录为空时，`ensureLibrary` 写入一份默认的 5×5 木板平台，供结构编辑器使用。

### 7.4 存档

存档不在 `assets/` 下。

| 路径                           | 内容                                  |
| ------------------------------ | ------------------------------------- |
| `GameSaves/<世界名>/<槽位>/` | 自由探索世界。当前槽位名为`default` |
| `GameSaves/profile.txt`      | 玩家显示名                            |
| `GameSaves/room_handoff.bin` | 大厅名单到专用服务器的交接            |

## 8. 编辑器

`editor.exe` 启动后进入模式选择。也可直接指定 `--texture`、`--item`、`--model`、`--animation`。

| 模式                | 输出                                               |
| ------------------- | -------------------------------------------------- |
| Texture Editor      | 图集贴图                                           |
| Item Model Editor   | `assets/materials/blocks/*.model`                |
| Entity Model Editor | 玩家与衣物体素部件                                 |
| Animation Editor    | `assets/entities/anims/*.animation` 与 `.hold` |
| Data Pack Editor    | `assets/data/` 数值                              |
| Structure Editor    | 启动`voxel-legend.exe --edit-structure`          |

结构编辑在游戏进程内进行：特权飞行，无重力，无生存结算，不绘制玩家模型。`E` 打开方块栏，左键拆除，右键放置，`F5` 将体积写回文件。体积锚点为方块坐标 `(8, 8, 8)`，尺寸 48×32×48。
